# 多城市扫描矩阵与受控跨页表

`ocr_matrix.py` 提取带城市行与明确数值列的矩阵，`matrix_evidence.py` 独立回放源文件、OCR词位置与映射哈希。全部原城市行先采集，再匹配研究名单；未映射者不猜行政代码。默认输出候选，绝不自动批准。

## 两个真实存档案例（2026-10-07）

|案例|实际覆盖|结果|保留边界|
|---|---|---|---|
|[河北2025年鉴8-8原图](https://tjj.hebei.gov.cn/hbstjj/tjnj/2025/zk/html/0808.jpg)|全社会用电量，2015、2020—2024；13城市＋2脚注口径行|90原数，90/90与原图逐格参考一致|石家庄市①、保定市①原标签独立，不能删①或合并|
|[重庆2025年鉴原PDF](https://tjj.cq.gov.cn/cslm/tjsjzl/202603/P020260330529346889373.pdf)原页593、596|20-1主表及续表3；38区县＋“#綦江区(不含万盛)”限定行；2024户籍人口与常住人口|78候选，78/78与原PDF文本行一致，并查看原页|续页只继承主表刊载年；人口指标和万人单位来自各页自己的表头|

两例使用真实官方文件的既有本地存档。河北本轮重下载TLS超时；**未伪造新增网络采集清单，未导入369城市主面板**。模式为 `archived_original`，证据一致性可通过，`origin.capture_matched=false`，正式筛选仍阻断。重庆PDF本身有文字层，本例专门渲染原页后走OCR矩阵链路；不是零文字层跨页扫描PDF的真实性能认证。区县案例用于版式测试，不改变用户城市研究单位名单。

公开复现脚本由使用者提供对应官方原件，哈希与固定参考值不符时失败，须重新核查而非自动修改参考：

```text
python examples/validate_matrix_reference.py --case hebei --input <0808.jpg原件> --output work/hebei_matrix
python examples/validate_matrix_reference.py --case cq --input <重庆2025年鉴原PDF> --output work/cq_crosspage
```

需要 `bootstrap.py --profile ocr` 的隔离环境。原书不随仓库分发，只提供来源、哈希、固定参考值与复现脚本。

## 工作流

1. `official_fetch.py` 取得官方原件；OCR保留原文件校验值。PDF用 `ocr_image.py --pages 593,596 --max-pages 2` 选择**原PDF页码**，不重写/切割PDF、不把页码改为1、2。未读全书仍明确报告。
2. 年份为列、城市为行且标题/单位唯一时，`ocr_matrix.py --propose-plan <plan.json>` 自动提出城市区间、年份列和原词锚点。不唯一时待核；提案并非完成取数。补充 `publication`，查看原页确认脚注与映射。
3. `ocr_matrix.py --plan <plan.json>` 输出候选/报告。所有必需参数同 `ocr_extract.py`，另有 `--plan` 或 `--propose-plan`。JSON映射不靠模型记忆：锚点格式为 `[原页码, OCR词索引]`；`x/body_y/city_x` 均为0—1页面坐标比例。
4. `audit_candidates.py` 重新验证源件/采集清单及映射，回放原行/列。映射变更使候选ID和计划哈希改变，旧审核不能沿用。
5. 单独的真实审核除了 `source_sha256`、实际审核人和具体理由，还须写 `plan_sha256`。无网络证据、无映射审核或存在待核项均不得选入正式面板。

直接官方PDF/图片可使用 `run_pipeline.py ... --matrix-plan <已核对的计划>`，连接获取、按原页OCR、矩阵提取和审核。默认单城OCR路径继续保守阻断未映射的多城市/多页文件，不因新后端存在而猜测跨页关系。

## 页/表/列约束

- 同一表的每页必须有自己的原词 `table_refs` 与同一印刷 `table_key`。不能把两个文件或两张不同表按位置拼接。
- 纵向续表带重复表头可分别映射；没有表头时仅在表号、模式和列位置一致，且 `continues_page` 指向此前已映射页时继承。列位移超过2%页面宽度就停止继承。
- 横向续表保留城市文字，不按行序或金额接近匹配；各页自己的指标和单位必须有原锚点。跨页继承年份必须指向同表已映射页实际印出的年份。
- 年份列和单位锚点不得来自相邻数值列。全表统一“单位：”可以引用。数值框明显跨列、多值挤单格、未解析空格、未知城市/半行断裂明确待核；原文缺失标记单独保留，不填零。
- 省/市总计和已识别分区域合计明确排除；“#”限定行、圈号与“(不含…)”保留原行标签，默认不映射到普通城市代码。脚注不是装饰，范围须审核。
- 重复城市—年—指标—范围键不静默去重；全部证据保留并报待核。CLI有部分记录但仍有待核时返回非零 `partial_pending`，下游阻断。
- `page_scope` 必须覆盖实际OCR工件的全部页。审阅后的有限表页可以明确 `explicit_table_page_subset=true`；这只声明研究所读页范围，不能宣称全书/全表已齐。

书目证据可选官方目录 `publication.context_chain`，或原PDF的 `document_page/document_quote`；图像也可使用有版年和年鉴路径的URL生成**仍须语义核查**的书目候选。不用省级发布者充当某一城市身份。

## 速度与可信度

Windows／RapidOCR本机单次公开脚本复现：河北90值OCR7.735秒、全流程8.968秒；重庆两原页78值OCR13.609秒、全流程15.138秒。原件在本地，模型权重已缓存，均不含找源/下载/人工审核/安装，不是速度承诺或Token、电耗计量。

固定参考一致与程序测试通过只说明这两个原件及对应映射能运行，不证明所有扫描布局准确。倾斜/曲线表格、无城市列续页、城市行断成两页、混合统计范围、未知复合表头仍待核。OCR分数与回放一致都不能替代原图字形复核。
